# Milestone v1.1: League Calendar & Contract Management

**Status:** ✅ SHIPPED 2026-03-13
**Phases:** 9-13
**Total Plans:** 9

## Overview

Added date-aware contract management with roster-wide visibility into all available actions, resolving ISS-001 (extension window awareness). Admin-configurable season calendar drives window gating for all 7 contract action types. New Contract Management Dashboard provides team-wide eligibility view with urgency-colored deadline countdowns.

## Phases

### Phase 9: League Calendar Data Model

**Goal**: Admin-configured season dates per year — oEXT deadline, tag/tender deadlines, B/R deadline, 5YO deadline, iEXT window, all auction dates
**Depends on**: v1.0 complete
**Plans**: 2 plans

Plans:
- [x] 09-01: SeasonCalendar model, migration, and CRUD endpoints
- [x] 09-02: Calendar admin UI with date entry form

**Details:**
- SeasonCalendar SQLAlchemy model with 27 nullable date fields grouped by deadlines, auction windows, and season markers
- Full CRUD API with 409 conflict detection for duplicate seasons
- Admin calendar page with 5 grouped card sections and season selector
- Frontend query/mutation hooks for calendar data

### Phase 10: Period Detection & Date-Aware Eligibility

**Goal**: Backend logic to determine current league period from configured dates, gate contract tools by window, enforce date constraints in eligibility checks
**Depends on**: Phase 9
**Plans**: 2 plans

Plans:
- [x] 10-01: Window status service and eligibility integration
- [x] 10-02: API response enhancement with window status

**Details:**
- WindowStatus dataclass and service mapping 7 contract actions to SeasonCalendar date fields
- Extension dual-window logic (oEXT deadline OR iEXT start/end)
- Date-aware eligibility gating woven into unified check_eligibility() dispatch
- WindowStatusSchema surfaced in bundled tools API response

### Phase 11: Roster-Wide Eligibility API

**Goal**: New endpoint returning contract action eligibility summary for all players on a team
**Depends on**: Phase 10
**Plans**: 1 plan

## Milestone Summary

**Key Decisions:**
- All 27 calendar date fields nullable — commissioner fills progressively
- PPE always-open (performance-based, no deadline window)
- Extension dual-window: oEXT deadline OR iEXT start/end
- Window statuses in bundled endpoint only, not individual tool endpoints
- Native date inputs for admin form (no date picker library needed)
- Dynamic column visibility based on window status in eligibility table

**Issues Resolved:**
- ISS-001: Extension window awareness — fully resolved with SeasonCalendar + window status service
- ISS-002: Franchise tag / tender eligibility queries querying wrong season for expired contracts

**Issues Deferred:**
- UAT-001 (Phase 4): Missing NFL kickoff eligibility rule for Drafted Rookie/UDFA contracts — requires external NFL schedule data
- ISSUE-001 (Phase 8): Extension eligibility needs player_scores table populated with historical data
- ISSUE-002 (Phase 8): Tags/tenders need multi-season contract history import

**Technical Debt Incurred:**
- Calendar timeline visualization deferred (Phase 13 focused on countdowns instead)
- Historical player score import pipeline not yet implemented
- Multi-season contract history import not yet implemented
