<task type="auto">
  <name>Task 1: Create roster and contract sync service</name>
  <files>src/app/services/roster_sync.py</files>
  <action>
1. Create `src/app/services/roster_sync.py` with:
   - `async def sync_rosters(client: MFLClient, session: AsyncSession, season: int) -> SyncResult`
   - Calls `client.rosters()` and parses with `MFLRostersResponse`
   - Requires Team and Player tables already populated (team_sync and player_sync ran first)
   - Build lookup dicts:
     - `team_lookup`: franchise_id → Team.id (from DB)
     - `player_lookup`: mfl_id → Player.id (from DB)
   - For each `MFLRosterFranchise`:
     - Look up team_id from franchise.id
     - For each `MFLRosterPlayer` on the roster:
       - Look up player_id from player.id (mfl_id)
       - If player not in player_lookup, log warning and skip (player may not have been synced)
       - Map MFL status to RosterStatus: "ROSTER" → ROSTER, "INJURED_RESERVE" → INJURED_RESERVE, "TAXI_SQUAD" → TAXI_SQUAD. If unknown status, default to ROSTER and log warning.
       - Upsert RosterEntry using (player_id, season) unique constraint
       - Upsert Contract using (team_id, player_id, season) unique constraint:
         - `salary`: Decimal(player.salary) — MFL returns string like "10.07"
         - `years_remaining`: int(player.contractYear) — MFL returns string
         - `designation`: player.contractInfo — string like "2019 EXT", "2021 1.02"
         - `contract_type`: Determine from salary/designation — initially set to NG (we'll refine classification in Phase 4 when the contract engine has full rules). Log a note that contract_type is placeholder.
         - `status`: ContractStatus.ACTIVE
         - `signed_season`: Parse from designation if possible (first 4 digits), else use current season
   - Return SyncResult with counts

Do NOT try to perfectly classify ContractType (NG/SD/FG) from MFL data alone — this requires bylaws rules (rookie draft position, salary thresholds) which are Phase 4 work. Set all to NG as placeholder and add a TODO comment.

Do NOT delete existing roster entries not in the current sync — an additive approach is safer. Mark missing players in a future phase if needed.
  </action>

<task type="auto">
  <name>Task 2: Create player scores sync service</name>
  <files>src/app/services/score_sync.py, src/app/models/player_score.py, src/app/models/__init__.py, migrations/versions/</files>
  <action>
1. The current schema doesn't have a player_scores table — we need one. Create `src/app/models/player_score.py`:
   - `PlayerScore(TimestampMixin, Base)`:
     - `player_id: Mapped[int]` — FK to players.id, indexed
     - `season: Mapped[int]` — season year
     - `week: Mapped[str]` — "YTD" for season totals, "1"-"17" for weekly, String(3)
     - `points: Mapped[float]` — Numeric(7,2), fantasy points scored
     - UniqueConstraint on (player_id, season, week)
   - Add relationship to Player model: `scores: Mapped[list[PlayerScore]]`
   - Update `src/app/models/__init__.py` to import PlayerScore
   - Generate Alembic migration: `uv run alembic revision --autogenerate -m "add player_scores table"`

2. Create `src/app/services/score_sync.py` with:
   - `async def sync_scores(client: MFLClient, session: AsyncSession, season: int, week: str = "YTD") -> SyncResult`
   - Calls `client.player_scores(week=week, year=season)` and parses with `MFLPlayerScoresResponse`
   - Build player_lookup: mfl_id → Player.id
   - For each `MFLPlayerScore`:
     - Look up player_id from score.id
     - If player not in lookup, skip (not all MFL players are in our system)
     - `points`: float(score.score) — MFL returns string like "156.70"
     - Upsert using (player_id, season, week) unique constraint
   - Batch process in groups of 500 with flush
   - Return SyncResult

   - `async def sync_historical_scores(client_factory, session: AsyncSession, years: list[int]) -> dict[int, SyncResult]`
     - For each year, create a new MFLClient instance (year-scoped URLs per research)
     - Call sync_scores for YTD totals for each year
     - Return dict mapping year → SyncResult
     - Add asyncio.sleep(client.request_delay) between years to respect rate limits

Do NOT sync weekly scores initially — YTD totals are sufficient for EPV calculations. Weekly granularity can be added later if needed.
  </action>
