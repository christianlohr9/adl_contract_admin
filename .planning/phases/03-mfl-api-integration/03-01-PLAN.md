  <name>Task 1: Install dependencies and create async MFL client with authentication</name>
  <files>pyproject.toml, uv.lock, src/app/mfl/__init__.py, src/app/mfl/client.py, src/app/mfl/exceptions.py, src/app/core/config.py</files>
  <action>
1. Install deps: `uv add httpx tenacity` and `uv add --dev pytest-httpx`
2. Add MFL settings to `src/app/core/config.py`:
   - `mfl_league_id: int = 60206`
   - `mfl_year: int = 2026`
   - `mfl_api_key: str = ""` (API key auth — simpler than cookie, works for export endpoints)
   - `mfl_username: str = ""` and `mfl_password: str = ""` (fallback cookie auth)
   - `mfl_base_url: str = "https://api.myfantasyleague.com"`
   - `mfl_request_delay: float = 1.0` (rate limit — space requests 1+ second apart)
3. Create `src/app/mfl/__init__.py` (empty)
4. Create `src/app/mfl/exceptions.py` with:
   - `MFLError(Exception)` — base
   - `MFLAuthError(MFLError)` — auth failures
   - `MFLRateLimitError(MFLError)` — 429 responses
   - `MFLAPIError(MFLError)` — unexpected API errors (include status_code, response_text)
5. Create `src/app/mfl/client.py` with `MFLClient` class:
   - Constructor: `__init__(self, year, league_id, base_url, api_key, username, password, request_delay)`
   - Context manager: `__aenter__` creates `httpx.AsyncClient` with 30s timeout, `__aexit__` closes it
   - `async def _authenticate(self)` — if api_key set, store it; else use cookie auth via login endpoint (GET /login with USERNAME, PASSWORD, XML=1), parse XML response for cookie_value
   - `async def _export(self, type_: str, **params)` — core method: builds params dict with TYPE, L, JSON=1; adds APIKEY param or Cookie header; uses tenacity retry (retry on HTTPStatusError, wait_exponential min=2 max=30, stop after 5 attempts); raises MFLRateLimitError on 429, MFLAPIError on other errors; enforces request_delay with asyncio.sleep between requests
   - Convenience methods returning raw dicts: `league()`, `rosters()`, `players()`, `player_scores(week="YTD", year=None)`, `free_agents()`, `salaries()`, `transactions(**params)`, `league_standings()`
   - Factory classmethod: `from_settings(cls, settings)` that creates client from Settings object

Do NOT use httpx cookie jar for auth — MFL uses a non-standard cookie flow where the login returns the cookie value in XML, and you pass it manually in subsequent requests. Parse it from XML and set as header.

Rate limit: Track last request time with `self._last_request_at` and enforce `request_delay` seconds between requests via `asyncio.sleep`.

<task type="auto">
  <name>Task 2: Create Pydantic response models for MFL API endpoints</name>
  <files>src/app/mfl/models.py</files>
  <action>
Create Pydantic v2 models for parsing MFL API JSON responses. MFL returns nested JSON with inconsistent casing and sometimes returns single items as dicts instead of lists.

Models to create:

1. `MFLFranchise` — from `league.franchises.franchise[]`:
   - `id: str` (franchise ID like "0001")
   - `name: str` (team name)
   - Optional fields: `conference: str | None`, `division: str | None`
   - Use `model_config = ConfigDict(populate_by_name=True)` for alias support

2. `MFLLeagueResponse` — wraps league endpoint:
   - `franchises: list[MFLFranchise]`
   - Use a model_validator(mode="before") to handle MFL's nested structure: response is `{"league": {"franchises": {"franchise": [...]}}}` — extract the list

3. `MFLPlayer` — from `players.player[]`:
   - `id: str` (MFL player ID as string)
   - `name: str` (display name)
   - `position: str`
   - `team: str | None` (NFL team abbreviation)
   - `birthdate: str | None`
   - `draft_year: str | None`
   - `draft_round: str | None`

4. `MFLPlayersResponse` — wraps players endpoint:
   - `players: list[MFLPlayer]`
   - model_validator to extract from `{"players": {"player": [...]}}`

5. `MFLRosterPlayer` — from `rosters.franchise[].player[]`:
   - `id: str` (player ID)
   - `salary: str` (salary as string, e.g. "10.07")
   - `contractYear: str` (years remaining as string)
   - `contractInfo: str` (designation like "2019 EXT")
   - `status: str` (roster status like "ROSTER", "INJURED_RESERVE", "TAXI_SQUAD")

6. `MFLRosterFranchise` — a franchise's roster:
   - `id: str` (franchise ID)
   - `player: list[MFLRosterPlayer]`
   - model_validator to handle single player as dict vs list

7. `MFLRostersResponse` — wraps rosters endpoint:
   - `franchises: list[MFLRosterFranchise]`
   - model_validator to extract from `{"rosters": {"franchise": [...]}}`

8. `MFLPlayerScore` — from `playerScores.playerScore[]`:
   - `id: str` (player ID)
   - `score: str` (points as string, e.g. "156.70")
   - Optional: `week: str | None`

9. `MFLPlayerScoresResponse` — wraps playerScores endpoint:
   - `scores: list[MFLPlayerScore]`
   - model_validator to extract from `{"playerScores": {"playerScore": [...]}}`

All models should handle MFL's inconsistency where a single-element list may be returned as a plain dict instead of a list — use a `_ensure_list` helper that wraps dicts in lists.

Do NOT add business logic to these models. They are pure API response shapes. Transformation to DB models happens in the sync service layer.
