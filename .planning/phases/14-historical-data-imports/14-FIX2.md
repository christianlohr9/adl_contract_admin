  <name>Task 1: Increase request delay and add adaptive rate limit handling</name>
  <files>src/app/core/config.py, src/app/mfl/client.py</files>
  <action>
The 1-second `request_delay` is far too aggressive for bulk historical fetches. MFL's rate limit appears to be a sliding window (not just per-second), so even retries with backoff don't help when the base rate is too high.

**1. Add backfill-specific delay setting in config.py:**
Add `mfl_backfill_request_delay: float = 6.0` to Settings class (alongside existing `mfl_request_delay: float = 1.0`). The normal 1s delay is fine for single API calls during regular sync; the 6s delay is for bulk historical fetches that make many sequential requests.

Why 6 seconds: MFL likely allows ~10 requests per minute. 6 seconds between requests = 10/min, staying safely under the limit. This is conservative but reliable.

**2. Improve rate limit retry in client.py:**
Change the `@retry` decorator on `_export_with_retry`:
- Increase `stop` from 7 to 10 attempts (more room for aggressive rate limits)
- Keep existing `wait_exponential(multiplier=2, min=4, max=60)` — this is fine
- Add a `before_sleep` callback that logs the retry attempt and wait time so we can monitor:
  ```python
  from tenacity import before_sleep_log
  ```
  Add `before_sleep=before_sleep_log(logger, logging.WARNING)` to the decorator.

Import `logging` at top of file if not already imported.

Do NOT change `request_delay` default (keep 1.0s for normal operations). The backfill delay is a separate setting used only by the backfill orchestrator.
  </action>

  </verify>
