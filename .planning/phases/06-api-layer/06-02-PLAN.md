**src/app/api/tools.py** — Contract tools router (prefix="/api/tools", tags=["contract-tools"]):

**Bundled endpoint (the key one from CONTEXT.md):**
- `GET /{player_id}` → PlayerToolsSchema — "What can I do with this player?" Query param `season: int` (default 2026). Calls ALL calculate functions in parallel (or sequentially — they're all async with DB access). Each call is wrapped in try/except — if a tool isn't applicable (raises ValueError or returns eligible=False), include the result as-is (it will have eligible=False with reason). If a service raises an unexpected error, set that tool to None in the response and log the error. This ensures one failing tool doesn't block the others.

  Implementation approach:
  1. Verify player exists (404 if not)
  2. Call each service: calculate_extensions, calculate_franchise_tags, calculate_tenders, calculate_buyout, calculate_5yo, calculate_ppe
  3. Convert dataclass results to schema instances
  4. Return bundled PlayerToolsSchema

  For dataclass → Pydantic conversion, since we use from_attributes=True, we can do `ExtensionResultSchema.model_validate(result, from_attributes=True)` on each dataclass result.

**Individual tool endpoints (for targeted queries):**
- `GET /{player_id}/extensions` → ExtensionResultSchema — season query param
- `GET /{player_id}/tags` → TagResultSchema — season query param
- `GET /{player_id}/tenders` → TenderResultSchema — season query param
- `GET /{player_id}/buyout` → BuyoutResultSchema — season query param
- `GET /{player_id}/5yo` → FifthYearOptionSchema — season query param
- `GET /{player_id}/ppe` → PPESchema — season query param

**Eligibility endpoint:**
- `GET /{player_id}/eligibility` → list[EligibilitySchema] — season query param. Check ALL 7 action types and return eligibility for each. Actions: extension, franchise_tag, transition_tag, erfa_tender, rfa_tender, buyout_restructure, fifth_year_option, proven_performance_escalator.

Each individual endpoint: verify player exists (404), call service, convert result, return. Keep error handling minimal — let service errors propagate as 500s (they indicate bugs, not user errors).

**Register in main.py** alongside existing routers.

IMPORTANT: Define specific sub-path routes (extensions, tags, etc.) BEFORE the catch-all `/{player_id}` route to avoid path conflicts. Or better: use `/{player_id}/all` for the bundled endpoint to avoid ambiguity.

Actually, use this URL structure to avoid conflicts:

- `GET /{player_id}/eligibility` → list[EligibilitySchema]

- etc.
