**src/app/api/cap.py** — Cap router (prefix="/api/cap", tags=["salary-cap"]):
- `GET /teams/{team_id}` → TeamCapSummarySchema — Full cap summary for a team. Query param `season: int` (default 2026). Calls get_team_cap_summary(). 404 if team not found (check team exists first).
- `GET /players/{player_id}` → PlayerCapDetailSchema — Single player cap detail. Query param `season: int`. Calls get_player_cap_detail(). 404 if no active contract found.
- `GET /teams/{team_id}/allotments` → AllotmentsSchema — Remaining allotments for a team. Query param `season: int`. Calls get_remaining_allotments() which returns dict like {"franchise_tag": 1, "buyout_restructure": 0, ...}. Convert to AllotmentsSchema.

**Add to src/app/api/teams.py:**
- `GET /{team_id}/snapshot` → TeamSnapshotSchema — The bundled team snapshot. Query param `season: int` (default 2026). This is the key endpoint from CONTEXT.md.

  Implementation:
  1. Load team (404 if not found)
  2. Call get_team_cap_summary(session, team_id, season) — this already includes player details
  3. Load roster entries (same query as existing roster endpoint)
  4. Call get_remaining_allotments(session, team_id, season)
  5. Bundle into TeamSnapshotSchema and return

  Add this endpoint to the existing teams router since it's team-scoped. Place it BEFORE `/{team_id}` to avoid path conflicts (or it should be fine since it's `/{team_id}/snapshot` which is more specific).

**Register cap router in main.py** alongside existing routers.

For dataclass → Pydantic conversion, use `.model_validate(result, from_attributes=True)` pattern.
