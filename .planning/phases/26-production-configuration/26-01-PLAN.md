<task type="auto">
  <name>Task 1: Complete .env.example and make CORS configurable</name>
  <files>.env.example, src/app/core/config.py, src/app/main.py, frontend/.env.example</files>
  <action>
1. Add `cors_origins` field to Settings in config.py — type `list[str]` with default `["http://localhost:5173"]`. Pydantic Settings parses comma-separated strings into lists automatically for `list[str]` fields, so `CORS_ORIGINS=http://localhost:5173,https://example.com` works out of the box.

2. In main.py line 73, replace hardcoded `allow_origins=["http://localhost:5173"]` with `allow_origins=settings.cors_origins`.

3. Rewrite .env.example to document ALL Settings fields with comments explaining each. Group by section (App, Database, CORS, MFL API, Sync). Use the actual defaults from config.py as example values. Do NOT include real credentials — use placeholder values like `your_username`.

4. Create frontend/.env.example with `VITE_API_URL=http://localhost:8000` and a comment explaining it.

Do NOT change any default values in config.py — just add the cors_origins field. The goal is documentation completeness, not behavior changes.
  </action>
  <verify>
- `python -c "from app.core.config import Settings; s = Settings(); print(s.cors_origins)"` prints `['http://localhost:5173']`
- grep CORS_ORIGINS .env.example shows the new field documented
- frontend/.env.example exists with VITE_API_URL
- .env.example has entries for all 15 Settings fields (14 existing + cors_origins)
  </verify>
  <done>
- Settings.cors_origins field exists with list[str] type and localhost default
- main.py uses settings.cors_origins instead of hardcoded list
- .env.example documents all backend env vars with comments
- frontend/.env.example documents VITE_API_URL
  </done>

2. In the `frontend` service, add an `environment` section passing `VITE_API_URL` (default to `http://web:8000` for inter-container communication — but note Vite needs this at BUILD time, so for the docker build it should be an ARG). Actually, since the frontend runs in the browser and calls the API from the user's browser, VITE_API_URL should point to the host-accessible backend URL. Add `VITE_API_URL=http://localhost:8000` as the default in docker-compose environment, and add a comment explaining this should match how users access the backend.

3. Add `rules/` volume mount to the web service if not already present (it is — verify and leave as-is).

Do NOT create a separate docker-compose.override.yml or docker-compose.prod.yml — keep it simple with one file and comments. Do NOT add health checks, resource limits, or production hardening beyond what's specified (that's Phase 27 territory).
