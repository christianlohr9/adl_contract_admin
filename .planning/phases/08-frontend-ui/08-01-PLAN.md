   ```
   pnpm add @tanstack/react-query @tanstack/react-table zustand nuqs
   pnpm dlx shadcn@latest add chart command dialog table badge select popover dropdown-menu progress alert scroll-area
   ```

2. Create `frontend/src/api/client.ts` — typed fetch wrapper:
   - BASE_URL from `import.meta.env.VITE_API_URL ?? 'http://localhost:8000'`
   - `api.get<T>(path)` function that fetches `${BASE_URL}${path}`, throws on non-ok, returns typed JSON
   - Keep it minimal — no interceptors, no retry logic (TanStack Query handles retry)

3. Create `frontend/src/api/types.ts` — TypeScript interfaces mirroring ALL Pydantic schemas:
   - From player.py: PlayerSchema, PlayerWithContractSchema
   - From team.py: TeamSchema
   - From contract.py: ContractSchema, RosterEntrySchema
   - From tools.py: EligibilitySchema, ExtensionOptionSchema, ExtensionResultSchema, TagOptionSchema, TagResultSchema, TenderOptionSchema, TenderResultSchema, BuyoutSalaryTierSchema, BuyoutOptionSchema, BuyoutResultSchema, FifthYearOptionSchema, PPESchema, PlayerToolsSchema
   - From cap.py: PenaltyResultSchema, PlayerCapDetailSchema, TeamCapSummarySchema, AllotmentsSchema
   - From snapshot.py: TeamSnapshotSchema
   - Use `number` for Decimal fields, `string | null` for optional strings, match field names exactly

4. Create `frontend/src/lib/format.ts` — formatting utilities:
   - `formatSalary(millions: number): string` — multiply by 1,000,000, format as USD with Intl.NumberFormat (no decimals)
   - `formatCapPercent(pct: number): string` — multiply by 100, format with 1 decimal place + "%"
   - `formatContractType(type: string): string` — map NG/SD/FG to readable names

5. Wrap app with QueryClientProvider in `frontend/src/main.tsx`:
   - Create QueryClient with defaultOptions: staleTime 5 min, retry 1
   - Wrap existing BrowserRouter + App with QueryClientProvider
   - Note: BrowserRouter is currently in App.tsx — move it to main.tsx so QueryClientProvider wraps everything
  </action>
  <verify>cd frontend && pnpm build — should compile without errors</verify>
  <done>API client, all TypeScript types matching Pydantic schemas, format utilities, and QueryClientProvider all in place; build succeeds</done>
</task>

<task type="auto">
  <name>Task 3: Create query hooks for all API endpoints</name>
  <files>frontend/src/api/queries/players.ts, frontend/src/api/queries/teams.ts, frontend/src/api/queries/tools.ts, frontend/src/api/queries/cap.ts</files>

1. Create `frontend/src/api/queries/players.ts`:
   - `usePlayers()` — not an endpoint, skip (players are accessed via team roster or search)
   - `usePlayerSearch(query: string)` — GET /api/players/search?q={query}, enabled only when query.length >= 2
   - `usePlayer(playerId: number)` — GET /api/players/{playerId}, returns PlayerWithContractSchema

2. Create `frontend/src/api/queries/teams.ts`:
   - `useTeams()` — GET /api/teams, returns TeamSchema[]
   - `useTeam(teamId: number)` — GET /api/teams/{teamId}
   - `useTeamRoster(teamId: number)` — GET /api/teams/{teamId}/roster, returns RosterEntrySchema[]
   - `useTeamContracts(teamId: number)` — GET /api/teams/{teamId}/contracts
   - `useTeamSnapshot(teamId: number)` — GET /api/teams/{teamId}/snapshot, returns TeamSnapshotSchema

3. Create `frontend/src/api/queries/tools.ts`:
   - `usePlayerTools(playerId: number)` — GET /api/tools/{playerId}/all, returns PlayerToolsSchema
   - Individual hooks NOT needed (bundled endpoint returns everything)

4. Create `frontend/src/api/queries/cap.ts`:
   - `useTeamCap(teamId: number)` — GET /api/cap/teams/{teamId}, returns TeamCapSummarySchema
   - `usePlayerCap(playerId: number)` — GET /api/cap/players/{playerId}
   - `useTeamAllotments(teamId: number)` — GET /api/cap/teams/{teamId}/allotments

All hooks should:
- Use queryKey arrays following [entity, id, sub-resource] pattern
- Set staleTime: 5 * 60 * 1000 (5 min)
- Only enable when required params are truthy (e.g., `enabled: !!playerId`)
