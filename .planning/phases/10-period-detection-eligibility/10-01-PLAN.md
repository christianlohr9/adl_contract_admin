  <name>Task 1: Create window status service</name>
  <files>src/app/services/window_status.py</files>
  <action>
Create a new service module that determines whether each contract action's window is currently open, closed, or unconfigured.

**Core design — tool-centric mapping, NOT abstract periods:**

Define a mapping from each action type (matching `eligibility.py` constants) to the SeasonCalendar fields that gate it:

- `extension` → checks `oext_deadline` (before deadline = open) AND `iext_window_start`/`iext_window_end` (between start/end = open). Either window being open means extensions are available.
- `franchise_tag` → checks `tag_deadline` (before deadline = open)
- `erfa_tender` → checks `tender_deadline` (before deadline = open)
- `rfa_tender` → checks `tender_deadline` (before deadline = open)
- `buyout_restructure` → checks `br_deadline` (before deadline = open)
- `fifth_year_option` → checks `fyo_deadline` (before deadline = open)
- `proven_performance_escalator` → automatic/no window gating (PPE is calculated based on performance, not a deadline action). Return always-open status.

**Create dataclass `WindowStatus`:**
```python
@dataclass
class WindowStatus:
    action: str
    status: str  # "open", "closed", "unconfigured"
    opens: date | None = None  # when window opens (if applicable)
    closes: date | None = None  # when window closes / deadline
    reason: str | None = None  # human-readable explanation
```

**Create async function `get_window_status(session, season, action) -> WindowStatus`:**
1. Load SeasonCalendar for the given season (query by season, cache-friendly — single row).
2. If no calendar exists → return `WindowStatus(action=action, status="unconfigured", reason="No season calendar configured for {season}")`.
3. Look up the relevant date field(s) for the action.
4. If the relevant date field(s) are None → return status="unconfigured" with reason explaining which date needs to be set.
5. Compare `date.today()` against the deadline/window dates:
   - For deadline-based actions: today <= deadline → "open", today > deadline → "closed"
   - For extensions (dual window): check oEXT first (today <= oext_deadline), then iEXT (iext_window_start <= today <= iext_window_end). Either open = "open".
6. Populate `opens`/`closes` fields from calendar dates for informational purposes.

**Create async function `get_all_window_statuses(session, season) -> dict[str, WindowStatus]`:**
Returns window status for all 7 action types in one call (loads calendar once).

**Important:** Use `datetime.date.today()` for the current date comparison. Do NOT pass the date as a parameter — this is always real-time. However, make the "today" value injectable via an optional `_today` parameter (default None = use date.today()) to enable future testing without mocking.

**Do NOT import from eligibility.py** — define the action type strings locally to avoid circular imports. Use the same string values as eligibility.py's constants.

Modify the existing `check_eligibility()` function to check window status BEFORE delegating to action-specific checkers.

**Changes to `check_eligibility()`:**

1. Add an import at the top: `from app.services.window_status import get_window_status`
2. After the action validation check but BEFORE the dispatch call, add window status check:
   ```python
   window = await get_window_status(session, season, action)
   ```
3. If `window.status == "unconfigured"`:
   - Return `EligibilityResult(action=action, eligible=False, reason=window.reason, rule_citation="No season calendar configured — commissioner must set dates before contract tools are available")`
4. If `window.status == "closed"`:
   - Return `EligibilityResult(action=action, eligible=False, reason=window.reason, rule_citation="Contract action window has closed for this season")`
5. If `window.status == "open"`:
   - Continue to the existing dispatch as before (player-level eligibility checks run normally).

**Add `window_status` field to `EligibilityResult` dataclass:**
Add an optional field: `window_status: str | None = None` and `window_closes: date | None = None`
Set these from the WindowStatus result for ALL outcomes (eligible or not), so the API always knows window state.

This requires importing `date` from datetime at the top.

**Key principle from CONTEXT.md:** Window gating is a prerequisite check. If the window is closed, the player-level check is irrelevant — don't even run it. But the calculated values (extensions, tags, etc.) are still returned by the tools API separately; eligibility just reports "not actionable right now."
