**Schema design guidance (from CONTEXT.md):**
- Schema should be designed based on deep knowledge of bylaws rules
- Whatever structure makes the contract engine easiest to build in Phase 4
- No seed data, no mocks — schemas only
- No business logic in models — just structure and storage

**Tech patterns (from 02-RESEARCH.md):**
- AsyncAttrs + DeclarativeBase
- Mapped[] + mapped_column() (SQLAlchemy 2.0 style, NOT old Column() style)
- Async Alembic env.py with run_sync bridge
- alembic init -t async (or manual async env.py)

**Domain model guidance:**
The old app used a single flat "roster" table. The new schema should be properly normalized:

- **Team** — 32 ADL franchises (franchise_id from MFL like "0001", name, conference, division)
- **Player** — NFL players (MFL player_id, name, position, NFL team, draft info)
- **Contract** — Player-team contract (salary, years, contract_type NG/SD/FG, designation, season signed)
- **RosterEntry** — Player on a team's roster for a season (status: active/IR/taxi, timestamps)
- **SalaryCapSnapshot** — Cap calculations at snapshot weeks (week 3, 7, 11, 16)
- **DraftPick** — Rookie draft picks (round, pick#, season, original/current owner)
- **Transaction** — Audit trail (type: trade/drop/add/waiver/extension/tag/tender, details)

Key relationships:
- Team has many Contracts, RosterEntries, DraftPicks
- Player has many Contracts (one per season/team), RosterEntries
- Contract belongs to Team and Player
- RosterEntry belongs to Team and Player, references Contract

  <name>Task 1: Create SQLAlchemy models</name>
  <files>src/app/models/base.py, src/app/models/team.py, src/app/models/player.py, src/app/models/contract.py, src/app/models/roster.py, src/app/models/salary_cap.py, src/app/models/draft_pick.py, src/app/models/transaction.py, src/app/models/__init__.py</files>
  <action>
1. Create `src/app/models/base.py`:
   - Base class: AsyncAttrs + DeclarativeBase
   - Common mixin with id (int, primary_key, autoincrement), created_at (datetime, server_default=now), updated_at (datetime, onupdate=now)

2. Create `src/app/models/team.py` — ADL franchises:
   - franchise_id: str (MFL ID like "0001", unique, indexed)
   - name: str (e.g., "Dallas Cowboys" — these are ADL team names mapped to NFL city names)
   - conference: str ("AFC" or "NFC")
   - division: str
   - Relationships: contracts, roster_entries, draft_picks

3. Create `src/app/models/player.py` — NFL players:
   - mfl_id: int (MFL player ID, unique, indexed) — the external identifier
   - name: str (display name)
   - position: str (QB, RB, WR, TE, PK, PN, DT, DE, LB, CB, S)
   - nfl_team: str (3-letter NFL team code, nullable — free agents)
   - birthdate: date (nullable)
   - draft_year: int (nullable — NFL draft year)
   - draft_round: int (nullable — NFL draft round)
   - Relationships: contracts, roster_entries

4. Create `src/app/models/contract.py` — Player contracts:
   - team_id: FK to Team
   - player_id: FK to Player
   - season: int (ADL season year this contract is for)
   - salary: Numeric(5, 2) (e.g., 10.07 = $10.07M)
   - years_remaining: int (contract years left including current)
   - contract_type: str (NG, SD, FG — determines cap penalty)
   - designation: str (the contractInfo string: "2019 EXT", "2021 1.02", "2021 UFA", etc.)
   - status: str (active, expired, bought_out, traded)
   - signed_season: int (season the original contract was signed)
   - Unique constraint: (team_id, player_id, season)
   - Relationships: team, player

5. Create `src/app/models/roster.py` — Roster entries:
   - team_id: FK to Team
   - player_id: FK to Player
   - contract_id: FK to Contract (nullable)
   - season: int
   - roster_status: str (ROSTER, INJURED_RESERVE, TAXI_SQUAD)
   - acquired_date: datetime (nullable)
   - Unique constraint: (player_id, season) — player can only be on one team per season
   - Relationships: team, player, contract

6. Create `src/app/models/salary_cap.py` — Cap snapshots:
   - team_id: FK to Team
   - season: int
   - week: int (snapshot week: 3, 7, 11, 16)
   - total_salary: Numeric(6, 2)
   - cap_penalties: Numeric(6, 2)
   - cap_space: Numeric(6, 2)
   - salary_cap: Numeric(6, 2) (the cap for that season)
   - Unique constraint: (team_id, season, week)

7. Create `src/app/models/draft_pick.py` — Draft picks:
   - season: int (draft year)
   - round: int (1-5)
   - pick: int (pick number within round)
   - original_team_id: FK to Team (who originally owned it)
   - current_team_id: FK to Team (who currently owns it)
   - player_id: FK to Player (nullable — null until pick is used)
   - Unique constraint: (season, round, pick)

8. Create `src/app/models/transaction.py` — Audit trail:
   - team_id: FK to Team
   - player_id: FK to Player (nullable — some transactions are pick-only)
   - transaction_type: str (trade, drop, add, waiver_claim, extension, franchise_tag, transition_tag, erfa_tender, rfa_tender, buyout, restructure)
   - season: int
   - details: JSON (flexible storage for transaction-specific data)
   - executed_at: datetime

9. Update `src/app/models/__init__.py`:
   - Import all models so Alembic can discover them
   - Import Base for use in Alembic env.py

Use SQLAlchemy 2.0 style throughout: Mapped[], mapped_column(), relationship() with type annotations. Use Enum types for constrained string fields where appropriate (contract_type, roster_status, transaction_type). Use Numeric for salary/money fields (NOT Float — floating point causes rounding errors with money).

  <name>Task 2: Initialize Alembic and generate initial migration</name>
  <files>alembic.ini, migrations/env.py, migrations/script.py.mako, migrations/versions/</files>
  <action>
1. Initialize Alembic with async template:
   - Run `cd /path/to/project && uv run alembic init -t async migrations`
   - This creates migrations/ directory with async-ready env.py

2. Configure `alembic.ini`:
   - Set script_location = migrations
   - Remove default sqlalchemy.url (will be set from config in env.py)

3. Configure `migrations/env.py` for async:
   - Import settings from app.core.config
   - Import Base from app.models (this triggers all model imports)
   - Set config.set_main_option("sqlalchemy.url", settings.database_url)
   - target_metadata = Base.metadata
   - Use async_engine_from_config pattern from research
   - The async template should handle most of this — just wire in our settings and Base

4. Generate initial migration:
   - Run `docker compose up -d db` to ensure PostgreSQL is running
   - Run `DATABASE_URL=postgresql+asyncpg://adl:adl_dev@localhost:5432/adl uv run alembic revision --autogenerate -m "initial schema"`
   - Inspect the generated migration file — verify all 7 tables are created with correct columns, constraints, and indexes

5. Apply migration:
   - Run `DATABASE_URL=postgresql+asyncpg://adl:adl_dev@localhost:5432/adl uv run alembic upgrade head`
   - Verify tables exist in PostgreSQL

6. Update docker-compose.yml web command to run migrations on startup:
   - Change command to: sh -c "alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload"
