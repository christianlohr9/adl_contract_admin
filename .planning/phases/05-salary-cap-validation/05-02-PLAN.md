  <name>Task 1: Unified eligibility validation service</name>
  <files>src/app/services/eligibility.py</files>
  <action>
Create `eligibility.py` — a single entry point for checking whether a player qualifies for any contract action.

**Result dataclass `EligibilityResult`:**
- action: str (e.g. "extension", "franchise_tag", "erfa_tender", "rfa_tender", "buyout_restructure", "fifth_year_option", "proven_performance_escalator")
- eligible: bool
- reason: str | None (None if eligible; clear explanation if not)
- rule_citation: str | None (specific bylaws rule reference, e.g. "Extensions §X-A: Players with 2+ years remaining are ineligible")
- prerequisites: list[str] (any conditions that must be met, even if currently eligible — e.g. "Must declare via Message Board by July 1")

**Main function `async def check_eligibility(session, player_id, season, action) -> EligibilityResult`:**

Dispatches to action-specific checkers. Each checker loads the player's active contract and validates against bylaws rules.

**Action-specific rules (from contracts.json and contract_tools.yaml):**

**"extension":**
- Delegate to `check_extension_eligibility()` from extensions.py (already implemented)
- Wrap result into EligibilityResult with rule_citation

**"franchise_tag" (EFT/NEFT/TT):**
- Must have 0 years remaining (expired contract)
- Team must not have already used their 1 tag this season (check allotment — Task 2)
- No more than 3 consecutive EFT/NEFT tags on same player (check prior season designations)
- Rule citation: "Franchise Tags §X-C: [specific rule]"

**"erfa_tender":**
- Must have 0 years remaining
- Previous contract signed at or below veteran minimum in one of previous two league years
- Players whose expired contracts are ERFA contracts are NOT eligible (prevents ERFA chains)
- Team must have tender allotment remaining (shares 2 with RFA)
- Rule citation: "ERFA Tenders: [specific rule]"

**"rfa_tender":**
- Must have 0 years remaining
- Contract must NOT include (from 2021 or earlier): EFT, NEFT, TT, NEFToff, TToff, FRFA, SRFA, ORFA, RRFA, B/R, EXT, 5YO
- Must not be multi-year UFA from 2023 or earlier
- Team must have tender allotment remaining (shares 2 with ERFA)
- Rule citation: "RFA Tenders §X-D: [specific rule]"

**"buyout_restructure":**
- Any player with any contract is eligible EXCEPT:
  - Players on Drafted Rookie or UDFA contracts are ineligible until the final year (years_remaining <= 1)
  - If 5YO exercised, eligible in year 5 (final year including 5YO)
- Team must have B/R allotment remaining (1 per season)
- Rule citation: "Buyout/Restructure §X-E: [specific rule]"

**"fifth_year_option":**
- Must be 1st round drafted rookie (designation matches round 1 pattern)
- Must be in 4th season of contract (signed_season + 3 == current season)
- Must not have already exercised 5YO (no "+" or "5YO" in designation)
- Rule citation: "5th Year Option: [specific rule]"

**"proven_performance_escalator":**
- Must be rounds 2-5 drafted rookie (check designation for draft round)
- Must be in 4th year of contract (eligible_contract_year = 4)
- Position must not be PK or PN (ineligible_positions from contracts.json)
- Rule citation: "Proven Performance Escalator: [specific rule]"

For each checker, load the active contract and relevant prior contracts as needed. Keep DB queries minimal — one query for current contract, one for historical if needed.

Do NOT duplicate the detailed calculation logic from Phase 4 services — this is purely "are you allowed to do this?" not "what would it cost?"

<task type="auto">
  <name>Task 2: Contract tool allotment tracking</name>
  <files>src/app/services/allotments.py, src/app/models/allotment.py, migrations/versions/</files>
  <action>
Create allotment tracking to enforce per-team annual limits on contract tools.

**Model `Allotment` in `allotment.py`:**
- Inherits from Base + TimestampMixin (same pattern as other models)
- Fields:
  - team_id: int (FK to teams.id)
  - season: int
  - action_type: str (e.g. "franchise_tag", "buyout_restructure", "tender", "july_1_tender")
  - player_id: int | None (FK to players.id, nullable — which player it was used on)
  - used_at: datetime (when the allotment was consumed)
- UniqueConstraint: Prevent double-recording (team_id, season, action_type, player_id)

Register in `src/app/models/__init__.py`.

**Create Alembic migration:**
- `alembic revision --autogenerate -m "add_allotments_table"`
- Verify migration creates the table correctly

**Service `allotments.py`:**

`async def get_remaining_allotments(session, team_id, season) -> dict[str, int]`:
- Query used allotments for team+season
- Compare against limits from contracts.json (`contract_tools_allotment` in contract_tools.yaml):
  - franchise_tags: 1 per season
  - buyout_restructures: 1 per season
  - tenders: 2 per season (shared between RFA and ERFA)
  - july_1_tenders: 2 per season
  - extensions: unlimited (return -1 or skip)
- Return dict of action_type → remaining count

`async def record_allotment_use(session, team_id, season, action_type, player_id) -> bool`:
- Check if allotment available
- If available: insert record, return True
- If exhausted: return False
- Does NOT commit — caller controls transaction

`async def has_allotment(session, team_id, season, action_type) -> bool`:
- Quick check: does team have remaining allotment for this action type?
- Used by eligibility service (Task 1) to gate checks

Wire `has_allotment()` into the eligibility checkers in `eligibility.py` where allotment limits apply (franchise_tag, buyout_restructure, tenders).
