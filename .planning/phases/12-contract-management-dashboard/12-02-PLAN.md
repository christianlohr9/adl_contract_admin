**Data transformation required:**
The API returns data grouped by action (each action has a list of eligible players). The table needs player-centric rows where each row is a player and columns show which actions they're eligible for + headline values. Transform: iterate action_groups, build a Map<player_id, PlayerRow> collecting each action's headline_value into the appropriate column.

  <name>Task 1: Data transformation and column definitions</name>
  <files>frontend/src/components/contracts/useEligibilityTable.ts, frontend/src/components/contracts/eligibility-columns.tsx</files>
  <action>
1. **Data transformation hook** (components/contracts/useEligibilityTable.ts):
   Create a custom hook or utility function that pivots the API response from action-grouped to player-centric rows.

   Input: `RosterEligibilitySchema` (from API)
   Output: Array of `EligibilityRow` objects

   Define `EligibilityRow` type:
   ```
   {
     player_id: number
     player_name: string
     position: string
     current_salary: number | null
     extension_value: number | null
     franchise_tag_value: number | null
     erfa_tender_value: number | null
     rfa_tender_value: number | null
     buyout_value: number | null
     fifth_year_value: number | null
     ppe_value: number | null
     eligible_action_count: number  // count of non-null action values
   }
   ```

   Transformation logic:
   - Create a Map<number, EligibilityRow> keyed by player_id
   - Iterate each action_group, for each player in the group:
     - Get or create the player's row in the map
     - Set the corresponding action value field (e.g., action "extension" → extension_value = headline_value)
   - Convert map to array
   - Calculate eligible_action_count as count of non-null action value fields
   - Use useMemo to memoize the transformation

2. **Column definitions** (components/contracts/eligibility-columns.tsx):
   Define TanStack Table columns following the pattern in RosterPage/SalaryCapPage:

   - **Player Name**: accessorKey "player_name", sortable, cell renders as text (no link — onRowClick handles navigation)
   - **Position**: accessorKey "position", sortable, render with Badge component
   - **Current Salary**: accessorKey "current_salary", sortable, cell uses formatSalary(), right-aligned
   - **Extension**: accessorKey "extension_value", sortable, cell uses formatSalary() or shows "—" if null, right-aligned
   - **Franchise Tag**: accessorKey "franchise_tag_value", sortable, cell uses formatSalary() or "—", right-aligned
   - **ERFA**: accessorKey "erfa_tender_value", sortable, cell uses formatSalary() or "—", right-aligned
   - **RFA**: accessorKey "rfa_tender_value", sortable, cell uses formatSalary() or "—", right-aligned
   - **B/R**: accessorKey "buyout_value", sortable, cell uses formatSalary() or "—", right-aligned
   - **5YO**: accessorKey "fifth_year_value", sortable, cell uses formatSalary() or "—", right-aligned
   - **PPE**: accessorKey "ppe_value", sortable, cell uses formatSalary() or "—", right-aligned

   Only include action columns where the corresponding window status is "open" (pass window_statuses to a function that filters columns). This keeps the table clean — no columns for closed/unconfigured windows.

   Use DataTableColumnHeader for sortable headers.
